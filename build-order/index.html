    Every package in one step only depends on packages in earlier steps, so a step can be built in parallel. Common, extras and non-free packages are shown with the PostgreSQL version selected above.

      How this was made
      • Every spec in main/{common,non-common,extras,non-free} was parsed with rpmspec -q for each OS directory it has (EL-8/9/10, F-43/44/45, SLES-15/16, AL-2023). Non-common specs were parsed once per PostgreSQL version directory (14 … 20) they are linked from.
      • Edges come from BuildRequires and from the Requires of each subpackage, matched against the binary package names and Provides of the other specs. Dependencies on OS packages are not shown.
      • Automatic dependencies (shared library sonames, pkgconfig(), python3.Xdist()) are only generated at build time, so they are missing here. Where a package links to a library it does not name in its spec, the build edge usually covers it, as with gdal's BuildRequires: proj98-devel.
      • When several packages provide one name (for example postgis or postgresql-server), the one for the same PostgreSQL version wins. When there is still more than one, the edge is shown as "any of" and does not change the build steps.
      • The host's rpm evaluated the specs with rhel, fedora, suse_version or amzn defined. SLES-only macros that the host does not have may hide a few SLES branches. On F-45, SLES and EL-8, Python version macros that call an interpreter missing on the host were pinned to that distro's Python.
